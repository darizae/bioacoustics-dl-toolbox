## 4. Shared decisions (avoid competing implementations)

- **Task type:** Introduce a serializable `TaskConfig` with `task_type` in `{"auto", "binary", "multiclass", "multilabel"}`. Default `auto` preserves existing behavior: with two classes it resolves to **binary represented by two logits**, and otherwise to multiclass. Explicit `multilabel` is mandatory for independent concurrent labels; an `auto` model must **never** infer multilabel from the number of classes. No changes to the ResNet encoder or default classifier layer sizes.
- **Class order:** One explicit, validated `class_to_index` mapping is authoritative throughout datasets, metrics, prediction, and checkpoints. Indices must be distinct and contiguous `0..C-1`; multi-label targets and output columns follow this order. Human-readable labels are not inferred from logits alone.
- **Targets and loss:** Binary and multiclass continue to use scalar integer class indices and cross-entropy-compatible two-/C-logit outputs. Multi-label uses a dense float32 multi-hot tensor `[C]` per sample / `[B,C]` per batch, `BCEWithLogitsLoss`, and independent sigmoid probabilities. All-zero targets are valid. The trainer must not use `argmax` or single-label confusion/AUC for multilabel.
- **Thresholds:** For multilabel, provide a validated probability threshold in `(0,1)` (default `0.5`), optionally one per class; compare `sigmoid(logits) >= threshold`. Threshold configuration is not a substitute for calibrating on held-out validation data. Existing binary/multiclass users retain softmax/argmax behavior.
- **Preprocessing:** A **single, deterministic, shared, no-augmentation** spectrogram→representation→normalization path must be callable from training and inference. Augmentation is training-only and occurs at its documented stage. MFCC must not receive `Amp2Db` after `M2MFCC`; preserve the historically trained MFCC representation where possible and document any unavoidable change. Align short-window padding and frame geometry in prediction.
- **Persistence:** Preserve existing six-key `trained_model.pt` payload and old `load_model(path)` behavior. Add **optional, versioned** metadata without silently changing defaults or altering model parameter names; old checkpoints must load. `CheckpointHandler` epoch-resume files are a separate contract: do not confuse them with exported `trained_model.pt` files.
- **Scope:** Pure-Python/PyTorch library APIs, no application-specific orchestration, no new mandatory dependencies if avoidable. Prediction returns structured in-memory results; Raven TSV export is an optional adapter.

Where a proposed interface conflicts with a currently documented public API, keep the old call signature working and add optional parameters. For a genuine breaking change, stop, document migration and a compatibility strategy, and flag for review before implementing.

## 7. Known hotspots in the supplied snapshot

- `audio/datasets.py`: `CsvSplit.split_fn()` takes non-cumulative `np.split` boundaries; `_split_with_seed()` checks seed by truthiness; `SpectrogramDataset` gives one scalar class per recording and maps binary classes without an explicit positive class to `"target"` or 0; `StridedAudioDataset` handles MFCC differently from `SpectrogramDataset`.
- `training/trainer.py`: `_train_epoch` and `_test_epoch` force int64 targets and use `argmax`; sample summaries assume one scalar label per item; binary AUC and multiclass confusion branches are incompatible with multilabel.
- `training/checkpoints.py`: `save_model` currently writes exactly six keys and lacks task type, normalization, sequence length, and threshold metadata.
- `tests/test_checkpoints.py`: four small tests only; extend with **unit tests** under `tests/` for the new surface.
